## 1. Что НЕ является проблемой (проверено, не трать на это время)

**Субагенты чистить не нужно.** Они не отдельные процессы, а участники живой сессии
Claude Code. Закрывается сессия — исчезают вместе с ней. Внешний планировщик до них не
дотянется, и в этом нет нужды: они не переживают закрытие терминала. Наблюдение «агент
висит 20 часов» означает лишь, что сессия открыта 20 часов.

Отсюда: **задача не про агентов и не про сессии**, а про файловые артефакты, которые
остаются на диске после них.

`~/.claude/jobs/` — 18 каталогов, суммарно 2.8 ГБ. Самые старые датированы 15 мая

**Но главное не возраст, а один каталог.** `~/.claude/jobs/489aae77/` занимает 2.7 ГБ из

каталогах, из них 1.6 ГБ — подкаталог `fresh_clone_check/` (очевидно, клон репозитория,
сделанный каким-то заданием и не убранный за собой).

Вывод: правило «удалять старше N дней» **не решит** основную проблему — крупнейший
пожиратель места свежий. Нужны два независимых правила: по возрасту И по размеру.

### 2.2 Рабочие копии репозиториев (worktree) — 23 штуки

Разбросаны по проектам: `Sensedar`, `quickexambot`, `free-ai-selector`,
`docker-deploy-playbook`, `checkmyskillsbot`. Остались от прошлых сессий.

### 2.3 ЛОВУШКА, на которой легко потерять работу

Наивная проверка `git status --short` внутри worktree показывает неотслеживаемые файлы
**родительского репозитория** — с путями вида `?? ../../../.beads/`. Из-за этого
13 из 23 копий выглядят «грязными», хотя своей несохранённой работы в них нет.

Правильная проверка — ограничить область самой копией:

```bash
git -C "$worktree" status --short -- .
```

С ней картина другая: **действительно грязных 10 из 23**, а не 13. Три копии
(`grace-migration`, `completion-reports` и другие) при наивной проверке выглядели
грязными, а на деле чисты.

Ошибка работает в обе стороны: можно и пропустить пустую копию, и — что хуже — принять
за пустую ту, где есть работа. Проверку писать аккуратно и покрыть тестом.

## 3. Что требуется сделать

Скрипт уборки плюс задание в планировщике (cron), **ежедневно в 07:00**.

Часовой пояс ноутбука уже `UTC+3` (совпадает со Стамбулом), поэтому дополнительных
преобразований времени не нужно — проверь `timedatectl` и подтверди это, а не поверь на
слово.

### 3.1 Каталоги заданий

Удалять каталог `~/.claude/jobs/<id>/`, если выполнено ЛЮБОЕ из:

1. возраст (по времени последнего изменения) больше 14 дней;
2. размер больше 1 ГБ И возраст больше 2 дней.

Второе правило — про случай `489aae77`: свежий, но чудовищный. Порог в 2 дня защищает
активное задание, которое прямо сейчас работает.

**Никогда не удалять** каталог задания, чья сессия ещё жива. Способ проверки определи
сам (например, по `state.json` внутри каталога и по наличию процесса) — и опиши в отчёте,
как именно проверял.

### 3.2 Рабочие копии

Удалять копию, только если выполнены ВСЕ три условия:

1. нет несохранённых изменений — проверка **с ограничением области**, см. п. 2.3;
2. нет коммитов, которых нет в основной ветке (`git log <main>..<branch>` пуст);
3. ветка копии слита в основную.

Иначе — пропустить и записать в журнал причину пропуска.

Удалять через `git worktree remove` (не `rm -rf`), чтобы репозиторий не остался с
битой записью о копии. После удаления копий выполнить `git worktree prune`.

### 3.3 Журнал

Писать в `~/.claude/housekeeping.log`: дата, что удалено, что пропущено и почему,
сколько места освобождено. Журнал должен отвечать на вопрос «почему эта копия ещё жива»
без запуска чего-либо вручную.

Ротация журнала: обрезать до последних 500 строк, чтобы он сам не стал проблемой.

## 4. Требования к качеству

1. **Режим проверки без удаления обязателен.** Первый запуск — только показать, что
   было бы удалено. Ключ вроде `--dry-run`. Установку в планировщик делать ТОЛЬКО после
   того, как ты покажешь вывод проверки и он окажется осмысленным.
2. **Тесты на логику принятия решения.** Как минимум: копия с несохранённой работой не
   удаляется; копия с неслитыми коммитами не удаляется; чистая слитая копия удаляется;
   ловушка из п. 2.3 не даёт ложного результата. Тесты должны работать на временных
   репозиториях, а не на реальных данных.
3. **Мутационная проверка.** Убери из скрипта проверку несохранённых изменений — тест
   обязан покраснеть. Тест, который не краснеет при поломке, бесполезен.
4. **Никаких `rm -rf` по шаблону.** Каждый путь удаления — вычисленный и проверенный.
5. **Скрипт не должен требовать прав суперпользователя.**

## 5. Что проверить перед сдачей

1. `--dry-run` на реальном состоянии: список совпадает с ожиданиями из раздела 2.
2. Запись в планировщике создана и видна в `crontab -l`.
3. Журнал появляется и читается.
4. Ни одна из копий с несохранённой работой не попала в список на удаление —
   на момент составления задания их **10 из 23**.

## 6. Промпт для запуска в отдельной сессии

Скопируй целиком:

```
Прочитай файл ~/ai-steward/Gena_Beeline_Local/python-ai-skills/claude-home/housekeeping/claude-housekeeping-task.md
и выполни описанное в нём задание.

Коротко: нужен скрипт ежедневной уборки артефактов Claude Code (каталоги фоновых заданий
в ~/.claude/jobs и осиротевшие git worktree в проектах ~/ai-steward), плюс запись в cron
на 07:00.

Главное, что нельзя испортить: в некоторых worktree лежит несохранённая работа, и
наивная проверка через `git status --short` даёт ложный результат, потому что показывает
файлы РОДИТЕЛЬСКОГО репозитория. Подробности и правильный способ проверки — в разделе 2.3
файла.

Порядок работы:
1. Сначала перепроверь замеры из файла сам — они сделаны 2026-08-12 и могли устареть.
2. Напиши скрипт с обязательным режимом --dry-run.
3. Покажи мне вывод --dry-run и дождись подтверждения.
4. Только после подтверждения ставь задание в cron.

Тесты обязательны, и каждый проверь мутацией: сломай проверку в скрипте и убедись, что
тест краснеет. Тест, не краснеющий при поломке, не считается.

Ничего не удаляй без моего подтверждения.
```
