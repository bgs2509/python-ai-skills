- `git-finish/SKILL.md`: utility skill for one repeated instruction — finish the current branch as documentation update, local merge into the base branch with conflict resolution, deletion of the branch and its worktree, and push **last**. The order is the skill's contract, not a preference: pushing first publishes a branch that still has to be cleaned up, and other machines then pull the half-finished state. Calling the skill is what supplies the explicit push authorization the global Git Push Policy demands — `--no-push` and any earlier failure stop the run with nothing pushed. Name chosen over `branch-finish` / `git-land` / `finish-branch` through `/best-approach` (82%), on the grounds that `git-commit` / `git-branch` / `git-finish` read as one group and all three are invoked in adjacent moments; `git-land` was the runner-up on precision, since Arcanist's `arc land` documents exactly this operation, but Phabricator appears nowhere in this repo. Base-branch detection deliberately does NOT trust `origin/HEAD`: in this very repository `git rev-parse --abbrev-ref origin/HEAD` exits non-zero while printing the literal `origin/HEAD`, and `git symbolic-ref --short refs/remotes/origin/HEAD` fails with "is not a symbolic ref" — both verified, hence the `show-ref` fallback over `main`/`master`. Worktree lookup is documented as requiring `rtk proxy`, because the RTK hook reshapes `git worktree list --porcelain` until the parse silently returns nothing (verified both ways). Walking the skill's own phases on a live branch caught a defect in the first draft before it shipped: for a branch checked out in the main clone the worktree lookup returns the repository root itself, so "path found → remove it" would have aimed `git worktree remove` at the workspace in use; the check now compares against `MAIN_ROOT` derived from `git rev-parse --path-format=absolute --git-common-dir` and removes only a path that differs from it. Written after doing the sequence by hand twice in one session, the second time to repair the consequence of skipping it: `progress-watch` lived only on an unmerged branch while `make install-symlinks` had already linked it, leaving two dangling symlinks in `~/.claude/skills` and `~/.codex/skills`
