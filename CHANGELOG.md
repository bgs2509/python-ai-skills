### Security
- `settings.json.template`: `enableAllProjectMcpServers` → `false` — it auto-approved MCP servers from any project's `.mcp.json`, which under `bypassPermissions` meant a cloned repo could bring an MCP server that executes without a single prompt (supply-chain hole; the 2026-08-31 audit's one real gap in the bypass trio — docs confirm deny rules DO bind in bypass mode, so the deny list itself was never dead)
- `settings.json.template`: `Read(researches/**)` → `Read(**/researches/**)` — the bare relative pattern matched only from the cwd root (the dir exists once, in `Prognosis/`), so the rule was inert in every other session. The `*secret*`/`*_token*` masks were briefly added here, then rolled back on review: the 2026-08-28 decision (false positives on legit `secrets.py`) stands, and the Security section of `CLAUDE.md` now says explicitly that those two masks bind agent discipline only, not the deny list
- `settings.json.template` + rendered `~/.claude/settings.json`: closed the two read-side bypasses found by the 2026-08-28 audit — (1) removed `Bash(cat:*)`, `Bash(head:*)`, `Bash(tail:*)`, `Bash(sudo cat:*)` from the allow list (they let terminal reads walk around every `Read(...)` deny rule); (2) bare cwd-relative deny patterns (`.env` family, `secrets.env`, `secrets/**`, `.netrc`, `.npmrc`, `.credentials.json`, and the `Edit(.env*)` family) prefixed with `**/` so they match at any depth, plus absolute `{{CLAUDE_HOME}}/secrets.env` and `{{CLAUDE_HOME}}/.credentials.json` entries. `defaultMode: bypassPermissions` deliberately unchanged (user decision). Residual gaps accepted: `grep`/`rg`/`find` stay allowed, `ssh * cat` (remote reads) stays allowed
- `settings.json.template`: closed the deny-list gaps vs the documented Security policy — added `Read` denies for `*.ppk`, `id_rsa*`/`id_ed25519*`, `.netrc`, `.npmrc`, `.credentials.json` (the OAuth store was not matched by `credentials.json`) and a single `credentials.*` glob; broad `*secret*`/`*_token*` globs deliberately NOT added (false positives on legit code like `secrets.py`). Removed the dead 50-entry `ask` list — inert under `bypassPermissions`, it only implied protection that never fired
- `~/.git-template` now delivers the promised gitleaks baseline: the bootstrap pre-commit hook falls back to `gitleaks protect --staged` when a repo has no `.pre-commit-config.yaml` (was: silent no-op). Hook SSoT moved into the repo (`claude-home/git-template/pre-commit`), installed by `install-claude-symlinks.sh` (copied, not symlinked). Verified live: fresh `git init` repo refuses a staged AWS-key leak, passes a clean commit
- MCP secret storage moved to level 2: `~/.claude.json` now holds only the documented `${CONTEXT7_API_KEY}` reference; the value lives in `~/.claude/secrets.env` (600) sourced from the shell profile — config auto-backups no longer replicate the secret. Added `Read(secrets.env)` deny-rule
- `settings.json.template`: deny-rules for `Read(**/.claude.json.backup.*)` and `Read({{CLAUDE_HOME}}/backups/**)` (a temporary `Read(.claude.json)` deny was lifted once the config held only the env reference) — the MCP config holds the `CONTEXT7_API_KEY`, and the audit found the model could read it (and its world-readable rotating backups) freely. Companion hardening applied on the machine: key rotated by the user, revoked key purged from config and backups, `~/.claude.json` → 600, `~/.claude/backups/` → 700
