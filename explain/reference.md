# explain — полная спецификация

## 1. Оси

### 1.1 `search` — откуда брать материал

| Значение | Источники | Когда |
|----------|-----------|-------|
| `none` | только то, что уже в контексте | объект передан целиком в запросе |
| `local` | репозиторий, файловая система, `bd memories`, `~/.claude/projects/*/memory/` | проект, кодовая база, локальный документ |
| `web` | WebSearch | внешняя концепция, свежие факты |
| `auto` | выбрать по объекту; можно комбинировать `local` + `web` | по умолчанию |

Стоящее правило репозитория: **библиотека/фреймворк → Context7** (`resolve-library-id` → `query-docs`) до любого объяснения её устройства; версия сверять с `uv.lock`.

### 1.2 `object` — что объясняем

Определяется из запроса автоматически, спрашивать не нужно. Особая процедура для `llm-output`:

1. Разбить вывод на смысловые фрагменты, процитировать каждый.
2. Для каждого фрагмента: термины из реестра → расшифровка по уровню `detail`.
3. Пересказ фрагмента обычными словами (Explanation Protocol: без образов).
4. Итог: «что этот вывод означает по делу» — 1–3 предложения.

Для `concept` (включая название/термин): сначала определение одним предложением, потом расшифровка по `structure`.

### 1.3 `audience` — кому

| Значение | Кто это | Влияние |
|----------|---------|---------|
| `child` | ребёнок | короткие предложения, никакого жаргона, аббревиатуры не употреблять вовсе |
| `novice` | новичок в теме, не программист | термины темы — через реестр с полным определением |
| `junior` | джу-программист | общепрограммистские термины можно без расшифровки, предметные — с ней |
| `senior` | опытный программист | без расшифровок, сразу по делу |
| `nontech` | человек вне программирования (бизнес, врач, юрист) | только термины из реестра, определения бытовым языком |
| `mixed` | смешанная аудитория | писать по самому неподготовленному участнику |

### 1.4 `detail` — насколько расшифровывать

| Значение | Правило |
|----------|---------|
| `full` | каждый термин при **первом** употреблении: расшифровка аббревиатуры + значение в скобках + минимум одно предложение смысла. В тексте не остаётся ни одного заранее неразобранного термина |
| `partial` | расшифровывать только термины вне базового набора аудитории (что входит в набор — определяется аудиторией, см. 1.3) |
| `none` | без расшифровок |

Связка с аудиторией по умолчанию: `child`/`novice`/`nontech` → `full`; `junior` → `full`; `senior` → `none`.

### 1.5 `register` — реестр терминов (всегда включён)

Не ось с выбором, а обязательная механика (измерение «синтаксис и грамматика»):

1. **До письма** составить реестр: `термин — определение (1 предложение)`. Реестр кладётся в конец ответа секцией «Словарь» (при `detail=full` обязателен, иначе опционален).
2. **В тексте** только формы из реестра. Один объект реальной жизни — одно обозначение: синонимная замена на ходу запрещена. Нельзя начать с «функция» и через абзац без предупреждения писать «метод» или «процедура» про то же самое.
3. **Новый термин понадобился по ходу** — сначала запись в реестр с определением, потом употребление в тексте.
4. **Проектные запрещённые формы** («лог» → «журнал» и т. п.) проверяет глоссарий-хук `claude-home/hooks/glossary.py`; скилл не повторяет проектный глоссарий, но обязан употреблять канонические формы.

### 1.6 `structure` — порядок изложения

| Значение | Форма |
|----------|-------|
| `layers` (по умолчанию) | суть в 3 предложениях → база (что это и зачем) → слой за слоем к деталям; каждый следующий слой опирается только на уже введённое |
| `summary-first` | TL;DR вверху, затем разделы; детали не наращиваются постепенно, а стоят по разделам |
| `direct` | сразу на целевом уровне `detail`, без наращивания и TL;DR |

### 1.7 `lang` — язык

`ru` по умолчанию (профиль пользователя). `en` — по запросу; словарь терминов в этом случае двуязычный (русский эквивалент в скобках), потому что Explanation Protocol требует русского эквивалента для каждого вводимого термина.

### 1.8 `sources` — grounding

| Значение | Правило |
|----------|---------|
| `on` (по умолчанию) | web-факт → URL источника; утверждение о коде → `файл:строка`; разбор вывода LLM → цитата фрагмента; библиотека → Context7/официальная документация |
| `off` | без проставленных источников (`--no-sources`) |

При `search=none` и `sources=on` источником служит сам переданный объект (цитата/ссылка на него). Флаг гипотезы (правило 5 `SKILL.md`) работает независимо от этой оси.

## 2. Разбор аргумента

1. Флаги `--preset`, `--audience`, `--detail`, `--search`, `--structure`, `lang` (через `--lang`), `--no-sources` применяются напрямую.
2. Естественный язык мапится: «как ребёнку / для ребёнка» → preset `child`; «как джуну» → `junior`; «как сеньору / эксперту» → `senior`; «для бизнеса / заказчика / не программиста» → `business`.
3. Не переданная ось — значение пресета или умолчание из таблицы в `SKILL.md`.
4. Не передан объект — единственный вопрос: «Что объясняем?» (шапка вопроса по global CLAUDE.md → Questions and Numbers).
5. Ось `object` в строку режима выводится всегда; остальные шесть осей + пресет, если задан.

## 3. Чек-лист самопроверки (перед выдачей ответа)

1. Каждый термин текста есть в реестре; ни одного вне реестра.
2. Ни одного синонимного замещения: один объект — одно обозначение от начала до конца.
3. При `detail=full`: каждая аббревиатура расшифрована, каждый термин имеет значение в скобках и ≥1 предложение смысла при первом употреблении.
4. Уровень соответствует аудитории (ребёнку — нет жаргона, сеньору — нет расшифровок).
5. При `sources=on`: у каждого внешнего факта есть источник (URL / `file:line` / цитата / документация).
6. Нет образов и метафор (global CLAUDE.md → Explanation Protocol, правило про образ).
7. Структура соответствует оси `structure`; каждый следующий слой опирается только на введённое.
8. Гипотезы помечены явно.

## 4. Связь с другими правилами

- **Global CLAUDE.md → Explanation Protocol** — база; скилл формализует и добавляет оси, конфликтов нет: всё, что запрещено протоколом, запрещено и здесь.
- **global CLAUDE.md → Questions and Numbers** — единственный допустимый вопрос (объект) задаётся с шапкой вопроса.
- **Глоссарий-хук** — проектные запрещённые формы; реестр скилла — объяснение-scoped, живёт в рамках одного ответа.
- **best-recommend** — объяснение внутри рекомендации подчиняется его правилу «как джуну»; этот скилл для автономных объяснений.
