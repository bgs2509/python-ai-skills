# /best-questions — Интерактивный разбор вопросов

> Разбираю вопросы по одному движком `best-research`, СТОП после каждого (кроме автоматического выбора по порогу — глобальный CLAUDE.md → Questions and Numbers), жду ответ.

## Вход

Аргумент — список вопросов ИЛИ описание задачи (сгенерирую вопросы сам). Без аргумента → спроси: «Какую задачу или список вопросов разбираем?». Количество вопросов НЕ ограничено — столько, сколько нужно для полного понимания.

## Что делает (тонкая обёртка)

1. **Сформируй очередь вопросов** — из аргумента или из анализа задачи.
2. **Для КАЖДОГО вопроса прогони движок `best-research`** — следуй его спецификации (`~/.claude/skills/best-research/SKILL.md`): исследование (код + Context7 + WebSearch + правила CLAUDE.md, уже загруженные в контекст) → мета-анализ → варианты + pros/cons → рекомендация по формату `best-recommend` (оценки `X% / Y%`). Это **переиспользование общего ядра по ссылке**, не передача управления.
3. **Один вопрос за раз, СТОП после каждого** — это специализация скила: не показывай два вопроса сразу, жди ответ.

## Интерактивный цикл (ЯДРО)

Для каждого вопроса `i` из `N`:

```
---
{шапка вопроса — глобальный CLAUDE.md → Questions and Numbers}
## Вопрос i/N: {текст вопроса}

{разбор по формату best-research: Контекст → Что сейчас в коде → Что нужно решить → Варианты (pros/cons) → Рекомендация (`X% / Y%` по формату best-recommend, со строкой «Свой вариант / ни один»)}

Твой выбор? (номер, свой вариант, "пропустить", "подробнее")
---
```

**СТОП** — жди ответ, НЕ переходи к следующему вопросу. Исключение — автоматический выбор по порогу (глобальный CLAUDE.md → Questions and Numbers): показать разбор, пометить выбранный вариант «[выбран автоматически]» и идти дальше.

### Обработка ответа
- **Номер** → записать решение, к следующему вопросу.
- **Автоматический выбор** → записать как решение с пометкой «[выбран автоматически]», к следующему вопросу.
- **Свой вариант** → записать как пользовательское решение.
- **"пропустить"** → отметить пропущенным, дальше.
- **"подробнее"** → развернуть варианты с деталями, примерами кода, ссылками.
- **Ответ порождает новые вопросы** → добавить в очередь, обновить N.

## Итоги

После всех вопросов:

```
## Итоги: N решений принято
1. **{Вопрос}** → Вариант {k}: {решение} [автоматический выбор | выбор пользователя]
2. **{Вопрос}** → Пользовательский / Пропущен
...
### Следующие шаги
- {действия на основе решений; результаты можно передать в /best-approach, /best-rank, brainstorming или plan}
```

## Правила специфичные для best-questions

1. **Один вопрос за раз** — никогда два одновременно.
2. **СТОП после каждого** — жди ответ; единственное исключение — автоматический выбор по порогу из глобального CLAUDE.md → Questions and Numbers.
3. **Без лимита вопросов** — 3 или 30, адаптируйся.
4. **Пропуск допустим** — пользователь может пропустить любой.
5. **Не реализовывать** — только анализ и решения, не писать код.

Всё остальное (исследование, Context7, объективность, формат варианта, оценки `X% / Y%`) — по спецификации `best-research`.

## Роль в семье best-*

- `best-questions` = **процесс** (итеративный разбор набора вопросов).
- НЕ управляет workflow transitions, НЕ вызывает process-skills (worker — не авто-переходит).
- Отличие: `best-questions` ведёт по **набору вопросов**; `best-approach` строит варианты **с нуля**; `best-rank` ранжирует **готовый список**.
- Движок разбора — `best-research`; формат рекомендации — `best-recommend`.
