# /best-recommend — Атом рекомендации

> SSoT того, КАК подавать одну рекомендацию: оценки `X% / Y%` + объяснение как джуну + источник + честный флаг неуверенности.
> Самый маленький скил семьи `best-*`. Переиспользуется через однострочный указатель.

## Когда применяется

1. Другой скил содержит указатель **«recommendation format → `/best-recommend`»** — подавай рекомендацию по этому формату.
2. Пользователь хочет рекомендацию по одному решению, объяснённую простым языком.

Это **атом**, не процесс: он не исследует варианты с нуля (`best-approach`), не ранжирует список (`best-rank`) и не ведёт по вопросам (`best-questions`). Он описывает только **форму подачи** готовой рекомендации.

## Контракт подачи рекомендации

1. **Две оценки на вариант.** Каждый вариант несёт пару `X% / Y%`; смысл X и Y, сумма 100 % со строкой «Свой вариант / ни один» и порог автоматического выбора заданы в одном месте — глобальный CLAUDE.md → Questions and Numbers; здесь не повторяются. Близкие варианты — назвать близкими явно, не подгонять разброс.

2. **Как джуну.** Объясняй простым языком, не предполагай, что термин очевиден. Любое неочевидное понятие (fast-forward, rebase, DIP, circuit breaker) сопровождай короткой расшифровкой и тем, **почему** это важно здесь и сейчас.

3. **Источник к каждой оценке.** Каждую пару `X% / Y%` сопровождай 1–2 предложениями «почему именно столько» со ссылкой на доказательство: best practice, официальная документация, паттерн в коде (`file:line`), результат Context7, отраслевой стандарт. Рекомендация без евиденса — слабая.

4. **Честный флаг неуверенности (анти-галлюцинация).** При малейшем сомнении — помечай явно как гипотезу: «*предположительно…, нужно проверить*», а не выдавай за факт. Никаких тихих допущений: если принял допущение, проговори его («исхожу из того, что…»). Это часть глобального анти-галлюцинация протокола.

## Формат блока рекомендации

```text
## 💡 Рекомендация
**Вариант A — X% / Y%** — {почему основной выбор; источник: <best practice / docs / file:line>}
**Вариант B — X% / Y%** — {в каких условиях лучше он; источник}
**Вариант C — X% / Y%** — {edge case; источник}
**Свой вариант / ни один — N%**

{Автоматический выбор или вопрос пользователю — по порогу: глобальный CLAUDE.md → Questions and Numbers.}
{Если есть неуверенность — явный флаг: «предположительно A, требует проверки B».}
```

## Что это НЕ

- Не оркестратор: `best-recommend` — атом, он **не переключает** workflow и не вызывает другие скилы.
- Не движок исследования: изучение состояния, мета-анализ и генерацию вариантов делает `best-research` — этот атом отвечает только за **подачу** итоговой рекомендации.

## Как переиспользовать

Добавить в нужный скил короткую строку:

```md
Формат рекомендации — по `/best-recommend`: оценки `X% / Y%` (глобальный CLAUDE.md → Questions and Numbers) + как джуну + источник к каждой оценке + честный флаг гипотезы при сомнении.
```
